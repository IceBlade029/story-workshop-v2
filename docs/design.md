## 1. 产品定位

故事工坊是一个大模型辅助故事创作桌面应用，核心是一条内容管道：

```text
情节细纲（故事真相）
  → 可见视图（知识边界：按标记确定性移除暂不明示事实，可人工修改）
  → 正文（多媒介：小说 / 剧本 / 漫画分镜）
```

产品不做三件事：不做通用聊天工具、不做自动写作流水线、不做流程审批系统。它做的是——让作者自由地讨论故事，把讨论结果安全地落成结构（情节大纲与设定），并严格地控制「读者在每个场景看到什么」。

典型使用流（三种入口，全部可选、可跳过、可混用）：

```text
入口 A：空白项目 → 全局讨论 → 点击「整理」→ 审阅草稿 → 提交正式版
入口 B：已有满意细纲 → 粘贴/上传为材料 → 「结构化此大纲」→ 直接进入生成管道
入口 C：直接在左侧大纲树写细纲 → 书写暂不明示标记 → 生成可见视图 → 生成正文
```

任何一步都不强制前置步骤：不讨论可以直接上传材料；不整理可以手写；不隐藏事实可以直接全明示生成。

## 2. 设计哲学

### 2.1 信任模型

大模型的能力已经足以处理创作过程中的大多数判断：话题切换、内容检索、层级归属、信息缺口识别、格式遵循。因此：

- 不给模型套流程机器（审批链、状态机、会话卡片、整理分级、压缩预算）——这些机制同时伤害模型和用户：模型被迫表演流程，用户被迫学机器语言。
- 模型能犯的错，用「可逆性」兜底，而不是用「预防流程」兜底。让模型犯错然后改正，比预防它犯错更便宜。

### 2.2 两条底线

整个系统只保留两类机制化控制：

1. **可逆性**：任何 AI 写入前自动快照；写入后提供变更摘要与 diff；用户可一键回滚。
2. **知识边界**：模型「能看到什么」由结构隔离决定，不由提示词决定。告诉模型「不要剧透」是挡不住泄密的——它知道的事就忍不住写出来；只有物理上不把内容喂给它，才算真的隔离。

判别标准：**约束「行为」→ 删（用提示词 + 回滚兜底）；约束「知识」→ 留（用结构隔离）。**

### 2.3 内容管道是产品内核

聊天、大纲树、材料、设定、正文都是围绕管道组织的：

```text
讨论空间（发散） ─┐
材料（外部输入） ─┼→ 大纲树（结构容器）→ 细纲 → 可见视图 → 正文
手写（直接输入） ─┘
设定（world/）    ┘  ← 与细纲平行的故事真相，供讨论/整理检索，永不进入正文生成器
```

管道上每个环节是一个独立的知识边界：

| 环节 | 能读什么 | 边界含义 |
|---|---|---|
| 讨论 / 整理 Agent | 项目全部（节点、草稿、设定、材料、对话、可见视图） | 无知识限制 |
| 可见视图（派生） | 由本地代码从细纲确定性生成，无模型参与（见 §6） | 披露决定由作者在细纲中标记表达 |
| 正文生成器 | 仅该场景可见视图 + 格式模板 | **物理上拿不到细纲、设定和标记** |

### 2.4 功能取舍判断标准

评估任何候选机制（流程、状态、步骤、指示、汇报式 UI）时，先用一个反问过滤：

> **如果模型不遵守它，产品还成立吗？**

- 成立 → 该机制是软件侧的真实能力（快照、白名单、hash 新鲜度、按钮触发），保留；
- 不成立 → 该机制依赖模型纪律（todo 进度更新、流程状态机、自我审计、汇报式进度），删除，改用软件强制或「提示词 + 回滚」兜底。

依据：模型可靠性的分水岭是「原生能力」与「流程纪律」——理解、检索、生成、判断、转译是训练目标直接优化的能力，可靠；跨时间维护状态、按契约执行多步流程、自我审计不是，任何把后者交给模型的设计都注定漂移（例：编程 agent 的 todo list 开局列出后往往不再更新——该动作对模型没有约束力）。

三条推论：

1. **状态与流程永远由软件维护**。模型无状态，只负责单次调用内的理解、判断与生成；任何需要模型"记得"或"自觉执行"的机制都不成立。
2. **软件侧已有的事件不得让模型转述**。进度、工具调用、变更等可由框架层事件驱动的信息，UI 直接消费事件；让模型"汇报"只是增加一次不可靠的转述。
3. **展示型 UI（计划、进度、摘要）若存在，价值在透明度而非纪律**——设计意图是如实反映，不是约束模型；模型不遵守时 UI 如实呈现，不假装。

## 3. 领域模型

### 3.1 大纲树：结构容器

- 层级：`overview（总纲）/ volume（卷）/ chapter（章）/ scene（场景）`，允许隐藏中间层级（如「卷 > 场景」时自动插入隐藏章）。
- 每个节点有三态内容：正式版（official）、草稿（draft）、元数据（hash 等）。
- **大纲树不是讨论入口**。节点选择只决定右侧面板查看哪个对象，永远不切换对话、不创建聊天室、不影响上下文。

### 3.2 全局对话：唯一的讨论空间

- 每个项目一条持续对话，不按节点分会话、不分话题卡片。
- 对话历史 = 追加式原始日志 + 派生摘要（见 §7）。
- 对话是**消息树 + 活动路径**：每条消息有单亲与兄弟分支；模型上下文只沿活动路径组装，分支内容不进上下文，除非用户切换过去。
- 保留最基础的时间线控制（与「会话结构」严格区分——时间线控制给用户裁判权，会话结构是模型 harness）：
  - **刷新**：对最后一条 AI 消息重新生成，旧回复保留为兄弟分支（`supersededBy` 标记），可随时切回查看，原始日志不改写；
  - **编辑用户消息 → 分支**：编辑不原地覆盖，追加「消息已编辑」系统事件保留旧文，活动路径从该点截断重走，旧尾部保留为分支；
  - **开启新话题**：显式按钮把当前话题归档为已结束会话，开始新的活动尾部；项目真相（大纲/设定/材料）全程共享；旧会话可浏览回看，Agent 可搜索（`search_conversation`）。
- 不做会话结构（地图、卡片、继承契约、跨会话检索规则）。
- 对话元数据记录**整理光标**（`lastOrganizedMessageId`，跨会话全局）：自光标之后的消息是「未整理内容」，是整理按钮的默认范围（见 §5.3）。
- 讨论本身是只读的：普通对话中的 Agent 没有任何写入工具。

### 3.3 材料：有身份的外部输入

- 材料是项目的一等对象：粘贴的文本、上传/拖入的文件、项目文件夹中已有的文件，统一收纳为 `materials/` 下的文件。
- 每条材料有稳定 id、名称、来源、hash、mtime。聊天消息只引用 `materialId`，不存正文。

### 3.4 可见视图：可编辑的知识边界资产

- 每个场景一份可见视图，由本地代码从细纲确定性生成：移除细纲中全部 `{{暂不明示：…}}` 标记区间（见 §6）。无模型参与、零 API 调用。
- 视图记录来源细纲的 hash 与「用户是否手改过」标记；细纲变更且未被手改时自动重新生成，手改过的视图受保护、不静默覆盖。
- 手改可见视图是设计内行为，不是绕路：微妙的信息处理（暗示、留白、节奏）由作者本人完成，系统只做「按标记机械移除」。

### 3.5 正文输出：派生资产

- 生成的小说/剧本/分镜落盘为 `outputs/<sceneId>.<format>.md`，不随窗口关闭丢失。
- 来源（可见视图或细纲）变更后自动标记失效，可一键重新生成。

### 3.6 设定：与情节平行的事实空间

- 世界观规则、角色设定/角色卡、事件编年史、地点、道具、伏笔等**不构成叙事时间轴**的故事真相，统一存放在设定空间（`world/`）。
- 设定按需创建：第一个设定落地时才出现，没有设定的故事完全不感知它。
- 设定没有草稿/正式之分：写出来就是事实，错误靠快照回滚兜底（它不像大纲有「提交正式版」的下游含义）。
- 设定不是材料：材料是外部输入，设定是项目内部真相。讨论中的未归类灵感落为 `type: 'misc'` 的设定条目，不引入「保存为素材」概念。
- 设定是知识边界的受益者：角色卡里可以完整写着「林默是凶手」——正文生成器永远读不到设定（§8.2）。

## 4. 数据模型与文件布局

### 4.1 项目文件布局

```text
<project>/
  project.json                    # 项目元数据（名称、创建时间等）
  outline.json                    # 大纲树结构：id、type、title、children 顺序、AI新增标记
  nodes/
    <nodeId>.md                   # 正式版内容
    <nodeId>.draft.md             # 草稿内容
    <nodeId>.meta.json            # 官方/草稿 hash、可见视图状态、时间戳
  conversation/
    history.jsonl                 # 原始对话日志（追加式，永不被改写）
    summary.md                    # 压缩摘要（派生资产，可被新摘要覆盖）
    meta.json                     # 对话元数据（整理光标、活动路径、活动会话）
  materials/
    <materialId>.md               # 材料正文
    index.json                    # 材料索引
  world/
    <assetId>.md                  # 设定正文（markdown 自由格式）
    index.json                    # 设定索引（id、type、title、hash、updatedAt）
  visible_views/
    <sceneId>.json                # 可见视图
  outputs/
    <sceneId>.<format>.md         # 生成的正文
  snapshots/
    <runId>/                      # 一次 AI 写入前的快照（受影响的文件副本）
```

### 4.2 核心类型

```ts
type NodeType = 'overview' | 'volume' | 'chapter' | 'scene';

interface OutlineNode {
  id: string;
  type: NodeType;
  title: string;
  children: OutlineNode[];   // 顺序即大纲顺序
  hidden?: boolean;          // 自动插入的中间层级
  aiCreated?: boolean;       // AI 创建、尚未审阅的标记（审阅后清除）
}

interface ChatMessage {
  id: string;
  parentId?: string;        // 单亲（消息树，不是图）
  childrenIds?: string[];   // 兄弟分支（刷新/编辑产生）
  supersededBy?: string;    // 被刷新/编辑取代（保留可切换查看）
  role: 'user' | 'ai' | 'system';
  content: string;
  timestamp: string;
  runId?: string;            // 关联的 agent run
  toolTrace?: ToolCallTrace[]; // 流式/取消/工具调用记录
  refs?: { materialIds?: string[]; nodeIds?: string[] }; // 引用，不存正文
}

// 会话：已开启新话题的归档段，时间线控制的最小单位（无继承契约）
interface ConversationSession {
  id: string;
  title: string;
  rootMessageId?: string;
  archivedAt: string;
}

interface Material {
  id: string;
  name: string;
  source: 'pasted' | 'uploaded' | 'workspace';
  hash: string;
  mtime: string;
  createdAt: string;
}

// 设定：type 是自由字符串 + 建议预设，不强制 schema
interface Asset {
  id: string;
  type: string;          // character | worldbuilding | timeline | location | prop | foreshadow | misc
  title: string;
  content: string;       // markdown 自由格式；模板是引导，不是约束
  hash: string;
  createdAt: string;
  updatedAt: string;
}

interface ConversationMeta {
  lastOrganizedMessageId?: string; // 整理光标：之后的消息 = 未整理内容（跨会话全局）
  activeMessageId?: string;        // 活动路径末端
  activeSessionId?: string;        // 当前活动会话
}

interface VisibleView {
  sceneId: string;
  content: string;
  sourceHash: string;        // 生成时所依据的细纲内容 hash
  userEdited: boolean;       // 用户手改后为 true，阻止静默覆盖
  needsRegeneration: boolean;// 细纲变更且视图被手改时置位（未手改则自动重生成）
  generatedAt: string;
}

// 暂不明示标记：披露意图的结构化表达，写在场景细纲文本中。
// 语法：{{暂不明示：内容}} —— 生成可见视图时整段机械移除，不做润色。
// 规则：不支持嵌套；插入者 = 作者（直接书写）或整理 Agent（转译意图 / AI 建议，见 §6.2）。

interface RunSummary {
  runId: string;
  taskKind: TaskKind;
  snapshotId: string;        // 写入前快照目录
  scope: string;             // 本次依据的人话描述
  changes: ChangeItem[];     // 逐个变更
}

type ChangeItem =
  | { action: 'draft_updated'; nodeId: string; beforeHash?: string; afterHash?: string }
  | { action: 'node_created'; nodeId: string; parentId: string; title: string }
  | { action: 'node_deleted'; nodeId: string }
  | { action: 'node_renamed'; nodeId: string; from: string; to: string }
  | { action: 'asset_created'; assetId: string; type: string; title: string }
  | { action: 'asset_updated'; assetId: string; beforeHash?: string; afterHash?: string };
```

### 4.3 新鲜度全部用 hash 比对，不用状态机

- 可见视图：生成时记录 `sourceHash`；细纲当前 hash 与之不符 → `needsRegeneration = true`。
- 材料：整理任务记录使用的材料 hash；材料被外部修改或重传 → 相关结果提示「材料已更新，可重新结构化」。
- 设定：索引记录每条设定的 hash；AI 基于旧设定改写时若设定已变更，回滚/重新整理时按 hash 对照。
- 任何地方都不存在 LLM 驱动的「就绪状态机」。

## 5. 交互设计

### 5.1 布局（三栏）

```text
┌──────────┬─────────────────────────┬──────────────────┐
│ 大纲 | 设定 │  全局对话（讨论空间）       │  右侧工作台        │
│ | 会话     │  - 消息流（流式/工具追踪）  │  互斥模式：        │
│ 只读导航   │  - 刷新 / 分支切换 /       │  节点/设定查看      │
│          │    开启新话题              │  / 变更摘要 / 可见 │
│          │  - 输入框 + 整理按钮       │  视图 / 正文       │
│          │  - 材料拖入/粘贴           │                   │
└──────────┴─────────────────────────┴──────────────────┘
```

- 左栏三个标签：**大纲**（大纲树）、**设定**（设定列表；第一个设定落地时才出现）、**会话**（已归档的旧话题，可回看与切回）。选中对象只改变右栏的查看对象，不改变中间对话。
- 消息尾部提供分支指示（「↑↓ N 个兄弟分支」）与刷新按钮；「开启新话题」按钮归档当前话题并开始新尾部。
- 右栏为互斥模式：浏览节点/设定（正式/草稿/版本历史）、变更摘要（AI 运行结束后自动切到）、可见视图编辑（场景节点）、正文输出列表。

### 5.2 三个入口

**入口 A — 讨论后整理**

1. 用户在全局对话区自由讨论（情节、设定、灵感混在一起都可以）。
2. 点击「整理」→ 启动 organize 任务，默认范围 = 整理光标之后未整理的全部对话。
3. 任务结束 → 右栏自动切到变更摘要；AI 产出按内容自行落入大纲草稿或设定，新建节点带「AI 新增」标记，新设定出现在「设定」标签。
4. 用户审阅 diff → 接受（清除标记）或一键回滚。
5. 满意后选中节点/子树 → 「提交为正式版」（见 §5.5）。

**入口 B — 已有细纲**

1. 用户粘贴文本，或把 `大纲.docx` 拖进项目/对话区。
2. 文本落为材料（聊天里出现一张材料卡片），系统轻提示：「结构化此大纲？」。
3. 点击后启动 organize 任务，**范围 = 该材料**（可追加说明，如「把其中『设定』部分拆成独立节点」）；目标仍由模型判断——材料里若同时含角色卡内容，混合产出大纲与设定。
4. 之后同入口 A 的 3–5 步。

**入口 C — 纯手写**

1. 用户直接在树里写/编辑细纲草稿，随时提交正式版。
2. 在细纲中书写暂不明示标记（§6.1），点击「生成可见视图」（细纲变更且未手改时自动重新生成）。
3. 审阅/手改可见视图，点击「生成正文」选择媒介。
4. 正文落盘 outputs/，可反馈修改重新生成。

### 5.3 整理任务：一个按钮，两个正交维度

只有一个「整理」按钮。它的职责明确：**消化范围内尚未整理的内容**。范围与目标由两个正交维度决定：

| 维度 | 谁决定 | 内容 |
|---|---|---|
| 范围 | 用户显式指定 | 默认 = 沿**活动路径**尚无有效整理覆盖凭据的消息及其附件；整理前可展开全文、逐项剔除/加回，也可加入独立附件；按钮提供「重新整理全部对话」覆盖选项。废弃分支里的内容需切回该分支再整理 |
| 目标 | 模型自己判断 | 范围内的内容在作品里是什么：够情节的落大纲草稿，够独立的落设定，混合产出，什么都不够就列缺口报告 |

**不做**「整理成大纲」与「整理成设定」两个按钮：双按钮会让用户的点击变成模型的补写暗示（讨论全是情节时点「设定」= 命令模型把情节编成设定；反之亦然），并制造「什么是大纲、什么是设定」的判定歧义。模型的判定边界是它自己该有的能力，应用不剥夺它。

- 任务成功结束后为实际消化的消息写入 `messageId + contentHash + runId` 覆盖凭据；附件按 hash 记录。`lastOrganizedMessageId` 只派生为活动路径已连续整理的最远位置，用于旧数据兼容和简要展示，不能越过被用户剔除的消息。
- 范围在变更摘要顶部显式展示，例如：

```text
本次范围：第 12–40 轮未整理对话（光标：#msg_12）
本次结果：新增 3 大纲节点（草稿）、2 张角色卡、1 条编年史、2 条待定灵感
```

- **混合产出是常态**：一次整理可同时创建大纲节点与设定；未归类但有价值的灵感落为 `type: 'misc'` 的设定条目（不引入「保存为素材」概念）。
- **不补写原则**（系统提示中的硬规则，同时约束大纲与设定产出）：

```text
整理只允许提取和归纳。不得新增故事事实。
讨论中未出现的设定不得凭空创建；信息不足时列出缺口，不补写；
有明确骨架时允许写入，但缺口必须以「待定：…」标注，不得伪装成事实。
AI 新提出的建议内容必须单独标注为「AI 建议」，不得混入草稿事实。
```

### 5.4 变更摘要与回滚

- 每次可写任务运行前：快照受影响文件（outline.json、节点文件、world/ 设定文件）到 `snapshots/<runId>/`。
- 运行结束：冻结写后快照，变更摘要固定比较该次运行的 before/after（文件级 diff + 结构操作列表 + 范围说明），历史结果不读取不断变化的当前文件。
- 用户操作：接受（保留草稿，清除整条返修链的「AI 新增」标记）/ 局部返修 / 整体返修 / 回滚。
- 返修沿用首次整理的来源，反馈直接进入 organize 可写任务而非普通讨论；局部返修由工具执行层限制可写资源，返修不推进整理覆盖。
- 整链回滚前必须确认当前项目仍匹配最新写后快照；发现后来手改或其他写入时拒绝自动恢复，避免覆盖后续工作。
- 单次运行内的改动整体可回滚，不需要逐条审批——这就是「让错误可逆」而非「预防错误」。

### 5.5 批量提交正式版

- 支持：单节点提交、按子树批量提交。
- 批量提交前显示影响汇总；默认排除带「待定：」标记的节点，用户可显式选择覆盖。
- 提交 = 草稿内容复制为正式版 + 更新 hash + 写快照（作为该节点版本历史的一页）。

## 6. 披露与正文管道

### 6.1 暂不明示标记：披露意图的结构化表达

披露决定权完全属于作者。作者在场景细纲中直接标注隐藏内容：

```markdown
第 12 场 天桥决斗
陈默（{{暂不明示：陈默是凶手}}）约林静在天桥见面。
两人对峙，陈默说："你早就知道了，对吗？"
```

- 语法：`{{暂不明示：内容}}`。不支持嵌套；标记区间在生成可见视图时被**整段机械移除**，不做润色——衔接由作者写标记时掌控。
- 只有「隐藏」一个档位，没有「暗示档」：「暗示」属于微妙处理，由作者在生成后的可见视图上手动完成（§6.4）。
- 跨场景的揭露节奏 = 标记出现在哪个场景的细纲里：第 1 场带标记、第 12 场不带 → 自动完成揭示。标记跟着文本走，无配置漂移。
- **没被标记的内容不是隐藏**——「没标记到」是作者的决定，不是系统的漏判。

### 6.2 标记的插入者

- **作者**：直接书写标记（最终裁决权）。
- **整理 Agent（转译意图）**：讨论中出现披露意图（「先不表明」「后面再揭示」「这里先别透露」），或材料中自带此类意图说明时，AI 整理细纲时把意图转译为标记——这是意图的忠实转译，不新增故事事实，不属于「补写」。
- **整理 Agent（主动建议）**：讨论中没有明确意图时，AI 可凭创作判断主动插入标记，但该标记属于「AI 建议」级：必须在变更摘要中显式列明，用户审阅时可见、可一句话让 AI 移除或手动删除。
- AI 不得编造披露意图——讨论从未涉及隐藏的内容，AI 不得自行决定隐藏。这一条与「不补写原则」同级。

### 6.3 可见视图生成（确定性，无模型参与）

点击「生成可见视图」→ 本地代码执行：读取细纲文本 → 移除全部 `{{暂不明示：…}}` 标记区间 → 落盘 `visible_views/<sceneId>.json`。

- 纯字符串处理：零 API 调用、即时完成、完全可测（结构上不存在泄漏）。
- 视图记录 `sourceHash` 与 `userEdited`。
- **自动重生成**：细纲变更且视图未被手改 → 自动重新生成；手改过的视图受保护，不静默覆盖。
- UI 提供视图与细纲的对照浏览，供抽查标记效果。

### 6.4 用户手改与覆盖保护

- 可见视图是纯文本，可在右栏直接编辑；编辑后 `userEdited = true`。
- 手改过的视图在细纲变更时不静默覆盖，提示「重新生成会覆盖你的手改，确认？」由用户决定。
- 生成正文时若视图与当前细纲不一致（`needsRegeneration`），提示用户先处理。

### 6.5 正文生成（硬知识边界）

- 正文生成任务只读两样东西：该场景的可见视图、所选格式的模板。
- **工具白名单中没有节点、设定、材料、搜索类工具**——正文生成器在物理上无法读到细纲、大纲树、设定、标记或任何其他场景内容。
- 输出落盘 `outputs/<sceneId>.<format>.md`；可见视图变更后提示重新生成；支持基于上一版输出的反馈重生成（输入为旧输出 + 反馈，仍只读可见视图）。

### 6.6 格式模板

- 模板 = 文本指南 + 元信息，如「小说」（叙事体、段落、中文引号）与「剧本」（场次 + 角色名:对白 + 动作括号）。
- 新增媒介（如漫画分镜：分格 + 画面描述 + 对白 + 分镜动作标注）只是新增一个模板，不引入任何新机制。

## 7. 对话、上下文与压缩

### 7.1 原始日志不可变

- `conversation/history.jsonl` 追加式写入：消息、工具调用记录、系统事件（压缩事件、运行摘要、消息编辑事件）全部落在这里。
- 任何压缩、整理、归档都不改写或删除日志行；日志是压缩出错后的恢复来源，也是证据来源。

### 7.2 上下文组装

- 每次模型调用时临时组装上下文：`压缩摘要（沿活动路径）+ 最近若干轮原文（沿活动路径）+ 当前输入`。
- 切到旧分支时，该分支的摘要惰性重算；分支内容不进活动路径上下文。
- **不自动注入大纲内容**。需要什么由 Agent 通过工具自行检索（§8.2）——这是「信任模型」的关键点：检索任务交给模型，应用只负责保证工具可用和日志完整。

### 7.3 简单压缩（两阶段）

自动压缩默认开启，触发条件为：`预计下一轮输入 + 预留回答空间 + 预留工具结果空间 > 模型上下文预算`（预留默认 ≈ 15% 窗口，回答按模型输出上限预留）。

1. **确定性安全裁剪**：从较早消息中移除高体积、可重新读取的内容——旧文件全文、旧搜索结果、已完成工具调用的冗长输出、重复读取的节点内容；保留资源 id 与 hash 引用。**永不裁剪**：用户原话、用户决定、未完成任务、最近几轮对话。
2. **一次摘要**：把裁剪后的更早前缀（沿活动路径）交给一次只读压缩任务，生成 `summary.md`（结构：已确认决策 / 已有事实 / 候选方案 / 待定问题 / 重要用户原话 / 引用清单）。原日志不动。分支路径各自维护摘要，切换后惰性重算。

压缩完成只显示轻量系统事件：

```text
已压缩较早的讨论上下文（覆盖第 1–34 轮，最近 6 轮保留原文）
```

用户可查看摘要、触发重新压缩、手动指定压缩重点；「指定重点」只影响摘要详略，不改变内容权威（候选不会因强调而变成事实）。压缩任务没有写入工具，不允许创建节点或修改草稿。

另提供只读**上下文视图**：展示一次模型调用实际收到什么（压缩摘要 + 保留原文范围 + 工具引用），供追溯与抽查；它是透明度工具，不是状态机。

### 7.4 压缩失败的恢复

顺序：再做一次确定性裁剪 → 缩小摘要范围 → 降低摘要长度 → 暂停新的模型运行并明确提示「原始对话没有丢失」。禁止把残缺摘要标记为成功。

## 8. Agent 运行时

### 8.1 运行循环

一次 Agent Run = 一次「模型 + 工具」循环：

- 支持流式输出、取消、工具调用追踪、引用标注；
- 事件全部记录进对话日志（作为 system 事件）与右侧工具追踪面板；
- 可写任务的写入模型见 §5.4。

### 8.2 任务类型与工具白名单（只按知识边界划分）

| 任务 | 用途 | 工具白名单 |
|---|---|---|
| `chat`（讨论） | 头脑风暴、分析、检索、回答 | `search_nodes`、`search_conversation`、`read_node`、`read_draft`、`list_nodes`、`read_asset`、`list_assets`、`list_materials`、`read_material`、`read_visible_view`。**无写入工具** |
| `organize`（整理） | 消化未整理内容：讨论/材料 → 大纲草稿与/或设定（含披露意图转译为暂不明示标记） | chat 全部 + `write_draft`、`create_node`、`rename_node`、`delete_node`、`write_asset`。**范围由用户指定，目标由模型判断**；写入全落草稿/设定并记录变更摘要 |
| `detail_fill`（正文生成） | 可见视图 → 正文 | `read_visible_view`、`read_format_template`、`write_output`。**不包含任何节点/设定/材料/搜索工具** |

可见视图生成不是 Agent 任务：由本地代码从细纲确定性派生（§6.3），无模型参与、无工具白名单。

规则：**普通讨论没有任何写入工具；一切写入都由明确按钮启动的任务执行。** 工具白名单只用于知识边界，不做行为限制（无审批、无风险分级、无策略引擎）。设定对 `chat`/`organize` 开放（角色一致性检查是设定的头号用途），对 `detail_fill` 关闭。

### 8.3 不做什么

- 没有 proposal / 审批 / 版本检查 / 锚点解析 / 回滚事务链——回滚由快照实现，且整体可回滚。
- 没有角色权限矩阵（role policy）——只有任务级知识边界。
- 没有整理批次生命周期、充分性四级分类、会话卡片、讨论地图。
- 没有按内容类型分目标的整理按钮（「整理成大纲」/「整理成设定」）——目标由模型判断。

## 9. 安全与可逆性

1. **快照**：可写任务运行前，复制 outline.json、全部受影响节点文件与设定文件到 `snapshots/<runId>/`；保留策略延后决定（默认全保留，因项目文件很小）。
2. **原子写与写锁**：所有落盘经原子写（临时文件 + rename），写锁防并发冲突。
3. **失效检测**：细纲 → 可见视图、材料 → 整理结果，全部由 hash 比对驱动（§4.3），无状态机。
4. **删除**：节点删除先进项目回收站（`trash/` 目录或带标记），永久删除需单独确认；已被正文/可见视图引用的内容保留最小证据快照。

## 10. 明确不做（非目标）

- 讨论地图、话题卡片、分支卡片、引用到新会话等会话层级结构（时间线控制——刷新、分支切换、开启新话题——保留，见 §3.2）
- Swipes 多版本候选（正文与讨论都不做：同上下文同任务的平行变体制造选择纠结；方向控制由刷新/分支提供）
- 注意力提示（当前关注/优先参考）及其衰减状态机
- 整理批次（OrganizationBatch）、充分性四级分类、生命周期状态
- proposal / 审批 / 风险分级 / 版本检查 / 锚点解析等写入审批链
- 角色权限矩阵、策略引擎、prompt 注入检测等行为控制
- 事实注册表、揭露曲线 UI、暗示档披露机制
- 场景披露配置 / 隐藏事实清单 / 泄漏复核（披露由作者在细纲中标记 + 确定性移除表达，见 §6）
- 预测式压缩预算、检查点数据模型、压缩权威状态标记
- 独立「导入大纲」产品主流程（结构化是 organize 任务的一种输入源）
- 「整理成设定」「保存为素材」等按内容类型分目标的独立写入入口（统一由整理按钮 + 模型判断目标 + `misc` 设定兜底）
- 设定 schema 强制（角色卡/世界观等字段不校验，模板只是引导）、设定与大纲节点的交叉链接
- 多故事分支、多用户、云同步、外部素材库导入
- 自动压缩的多模型切换（固定模型，失败按 §7.4 恢复）
