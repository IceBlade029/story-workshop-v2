> 状态：决策文档（随讨论持续更新）

## 1. 产品形态定位

故事工坊是一个**故事创作辅助 AI 应用**，不是编程 agent。交互对标两层：

| 层 | 对标对象 | 负责 |
|---|---|---|
| 聊天层 | ChatGPT 网页版 / DeepSeek 网页版 | 讨论空间的交互完成度（本产品 90% 时间在这里） |
| 写作层 | Sudowrite / NovelCrafter | 讨论结果落成作品结构的工作流（就近操作、卡片式产出） |

**明确不采用的编程 agent 范式**（调研结论：不适用于写作场景）：

- 工具调用卡片流（Cline 式）——工具活动应像 DeepSeek「联网搜索中…」一样轻量、折叠、一闪而过；
- 每消息 checkpoint + Compare/Restore——写作的可逆已由 草稿/正式版/版本历史/消息分支 承担；
- Plan/Act 双模式——讨论只读 + 整理按钮已是同一语义，无需新概念；
- diff 逐 hunk 审查——散文不是代码，变更摘要应是自然语言；
- 权限模式/审批——无危险操作，不需要。

**保留的行业共性**：可逆性（已有机制）、知识边界物理隔离（产品灵魂）、完成通知、快捷键文化。
**从编程 agent 借鉴并普适化的能力**：调用透明度（见 §4.7）——"应用给模型发了什么、模型返回了什么"对非技术用户同样有价值。

## 2. 顶层形态：两个对等全屏模块

```
┌────────────────────────────────────────────────┐
│ 顶部栏：项目名    [情节讨论] [正文写作]    ⚙      │
├────────────────────────────────────────────────┤
│  讨论模块（全屏，独占界面）                       │
│  正文模块（全屏，独占界面，tab 切换进入）          │
└────────────────────────────────────────────────┘
```

- 「情节讨论」「正文写作」是对等的一等公民模块，各自占满整个窗口，通过顶部 tab 切换（恢复 v1 的 ModuleSwitcher 形态，v2 曾错误地把正文压缩进右栏）；
- 模块 UI 状态互相独立：讨论模块的选中节点、正文模块的选中场景互不干扰，切换 tab 不丢状态；
- 设置 = 顶部齿轮，**弹窗**（模态对话框，全局配置不属于创作上下文，不占右栏、不占模块位）。

## 3. 核心模型：输入 → 整理 → 知识库

**用户可见的只有两个概念**：

```
输入（任何形式：消息 / 粘贴 / 上传 / 拖入 / 项目内文件）
  → 整理（唯一的"入库"动作，范围 = 光标后未整理，可用自然语言补充）
  → 知识库（大纲 + 设定——唯一面向用户的结构分类）
```

「材料」概念整体移除（design.md §3.3 修正）。三个产品入口（讨论→整理 / 粘贴上传 / 手写）本质是同一模型——**输入**的不同形式，程序层面不分类、不引导、不设引导卡。

### 3.1 UI 层

| 现状（机器概念） | 修正后 |
|---|---|
| 「粘贴为材料」模式切换按钮 | 删除。粘贴就是输入，发送即可 |
| 「上传文件」「收纳项目文件」按钮 | 合并为一个「附件」按钮（ChatGPT 式），拖入/上传即附件消息 |
| 聊天里「材料」卡片 + 「结构化此大纲？」按钮 | 附件行（图标 + 文件名 + 大小 + 全文可展开 + 「已更新」标记），无分类语言、无弹窗 |
| 收纳 = 移动文件进 materials/ 并删除原文件 | 不移动、不删除原文件；附件面板提供「项目文件」分组可选 |
| organize 范围含「指定材料」 | 范围 = 未整理 / 全部 + 自然语言 note（"只整理我刚上传的文件"） |
| 「材料已更新，可重新结构化」 | 保留 hash 新鲜度机制，呈现为附件行「已更新」标记 |

### 3.2 工程层（用户不可见）

- 目录 `materials/` → `attachments/`，类型 `Material` → `Attachment`，IPC `material:*` → `attachment:*`，工具 `list_materials/read_material` → `list_attachments/read_attachment`，`refs.materialIds` → `refs.attachmentIds`，相关测试同步改名；
- 粘贴长文本（阈值 ≈ 2000 字）自动识别为附件消息：输入框内轻提示「将作为附件发送」，发送后消息显示为附件行 + 全文可展开；对话日志存引用不存正文（防日志臃肿、支持 hash 新鲜度）；
- 保留机制：附件全文落盘 + 日志存引用、知识边界工具白名单（chat 只读、detail_fill 物理隔离）、`misc` 设定兜底（讨论碎片直接入库）。

## 4. 讨论模块

### 4.1 聊天体验（按 DeepSeek 网页版完成度一次做齐）

| 项 | 决策 |
|---|---|
| 流式渲染 | 流式期间**即时渲染 markdown**（当前是 `<pre>` 原文，完成后才渲染，体验断裂） |
| 消息操作条 | 每条消息 hover 显示：AI → 复制 / 重新生成 / 编辑 / ⓘ 调用详情；用户 → 复制 / 编辑 |
| 消息编辑 | 就地编辑重发（点击自己消息编辑，非弹窗）；旧版本折叠为「查看上一版」（底层消息树/分支机制保留，UI 弱化） |
| 思维链 | 折叠为「已深度思考（X 秒）」可展开；不展示原始文本尾部 |
| 模型/思考切换 | 移到输入框上方（当前埋在设置页）；思考模式开关 + 模型选择 |
| token/上下文 | 输入框附近显示「已使用 X%」轻进度 |
| 错误处理 | 消息流内错误呈现 + 「重试」按钮（当前仅 toast） |
| 输入框 | 附件按钮 + 拖拽 + 发送后乐观渲染（先落本地消息再启动 run） |
| 会话 | 自动命名、一键新建（去掉弹窗命名）；「开启新话题」在对话流 header 右上角 |
| 智能滚动 | 用户回看历史时不强制滚底；出现「跳到底部」浮标 |
| 完成通知 | 窗口后台时任务完成发桌面通知（可关） |

### 4.2 整理交互（核心动作）

- 「整理」按钮保持在**输入工具条原位**，不强化为主按钮，去掉 (N) 计数；
- 工具条构成：`[附件] [整理]`（新话题移入 header 右上角）；
- 对话流顶部（header 下）一条**很淡的存在性提示**：「有新内容未整理 · 查看」——muted 小字，无计数、无时间、无催促感（反面案例：手机 App 红点式持续提示会打扰发散中的用户）；
- 点击「查看」才展开详情：消息起止范围 + 附件清单 + 追加说明输入框 + 确认整理；
- 「重新整理全部」收敛为详情区的溢出项（危险操作保留确认）；
- **变更摘要详情在对话流内展开**：organize 总结消息下方可展开变更列表/diff（Cline 式，消息内展开），不占右栏。

### 4.3 系统事件降噪

- 运行开始/结束合并为**一行轻提示**（居中细条），变更明细不进对话正文；
- organize 完成后：对话流出现一条 **AI 自然语言总结消息**（系统 prompt 增加"结束时向作者总结"要求：整理范围、产出清单含可点击跳转、待定缺口）；
- 右栏「变更摘要」面板移除，organize 完成**不再强切右栏模式**（保护用户未保存的编辑，P0-3 修复）；
- **沙箱隔离（2026-08-06 修订）**：讨论与正文是两个隔离沙箱，中间只靠大纲树场景链接。写作任务（`detail_fill` 正文生成、`revise` 就地改写）**不产生任何对话消息**——无运行开始/结束、无 AI 回答、无「已生成/已改写 → 打开」提示（单场景生成只有几秒，用户直接等待结果，无批量需求）。写作产物只留在 `outputs/` 与调用详情记录里；讨论上下文组装与 `search_conversation` 永不含写作产物；写作任务也不再计入「未整理」。

### 4.4 运行中轻量进度

- 基于现有 toolTrace 事件，显示一行「正在整理…（已写入：第 3 章草稿 / 角色卡·林默）」——像 DeepSeek「搜索中…」一样轻量，不打断阅读；
- 取消/出错时：已产生的文本保留为可复制的失败块（P0-1 修复：不再全部消失）。

### 4.5 会话管理

- 左栏「会话」tab 保留（归档话题回看）；
- 新话题 = 自动命名 + 一键归档（header 右上角按钮）。

### 4.6 右栏：知识库对象详情查看器

**右栏职责收敛为单一功能**：查看/编辑当前选中的知识库对象（节点、设定）。只保留两种模式：

| 模式 | 内容 |
|---|---|
| 节点详情 | 草稿 / 正式版 / 版本历史 / 重命名 / 子节点 / 提交为正式版 / 删除（**去掉可见视图、正文 tab**——已归正文模块） |
| 设定详情 | 标题 / 类型 / 内容编辑 / 删除 |

**移出右栏的功能**：

| 原模式 | 去向 |
|---|---|
| `settings` | 顶部齿轮 → 弹窗（§2） |
| `context`（会话级上下文视图） | 移除，由每消息级「调用详情」替代（§4.7） |
| `summary`（变更摘要列表） | 移除，organize 完成 = 对话流 AI 总结消息，详情消息内展开（§4.2） |

**回退按钮 = 查看历史栈**（浏览器式 ←）：

- 左栏点击节点/设定 = 直接替换当前对象（**不压栈**，避免点 10 个节点回退 10 次）；
- **跳转类操作压栈**：对话流内链接（organize 总结消息的产出清单、节点链接）→ 跳转后右栏 header 显示 `←` + 对象名，点击回到跳转前正在查看的对象；
- 语义 = "回到我跳转前正在看的那个节点/设定"（覆盖"整理完成后点了新节点链接，想回去继续编辑刚才草稿"的场景）。

**空态**：未选中任何对象时显示**项目概况**（大纲节点数 / 设定数 / 输出数等轻统计，静态信息，非引导卡）。

### 4.7 每消息级「调用详情」（对话透明度）

**概念修正**（design.md §7.3 修订）：上下文透明度不按"整个会话"预测式呈现（现状 `inspectContext` 是"下一次调用将收到什么"），而是**每条 AI 回答级别回看**："这次调用应用给模型发送了什么、模型返回了什么"。用户掌控对话不是黑盒，锚点在每一条回答。

**数据**（新持久化，随对话生命周期）：

```
conversation/runs/<runId>.json
├─ 头部：taskKind · scope · 状态(done/error/cancelled) · 耗时 · 轮数 · token 用量
├─ 发送区：
│   ├─ 系统提示（全文，折叠）
│   ├─ 组装后的消息清单（引用式：角色 · 来源[原文/摘要] · 字数）
│   ├─ 若走了压缩：摘要锚点 + 摘要全文 + 保留原文区间
│   └─ 工具白名单
└─ 返回区：
    ├─ 工具调用序列（名称 · 参数 · 状态 · 错误 · 耗时）
    └─ 最终回答（标注"见本条消息"）
```

**UI**：

- 入口：消息操作条「ⓘ 调用详情」，有记录才显示；无 AI 消息的 run（如 detail_fill 完成提示）在其系统消息上挂入口；
- 形态：弹窗；
- 发送区引用式展示（不堆原文）；想看原文 → 点消息跳回对话流定位；
- **手动重压缩/指定重点**入口挂在调用详情弹窗内：该 run 走了压缩时显示摘要 + 「重新压缩（可指定重点）」按钮，作用于该分支——压缩从"会话级管理"变成"发生在某条消息处的可见操作"。

**工程**：run-loop 结束时写调用记录（扩展 RunRecorder）；`prepareChatContext` 的压缩决策（anchor/keptFrom）随 run 记录；IPC 加 `run.inspect(runId)`；renderer 消息操作条加入口。**全部任务记录**（chat / organize / detail_fill / revise / 压缩任务），一致透明。
**入口位置（2026-08-06 修订）**：对话任务的 ⓘ 入口在消息操作条与运行轻提示上；写作任务（沙箱隔离后讨论中零痕迹）的 ⓘ 入口在**正文模块工具栏**（最近一次写作任务的记录）。

## 5. 正文模块

### 5.1 布局

```
┌──────────┬────────────────────────────────────────┐
│ 场景列表   │ [格式选择] [生成正文] [复制全文]           │
│ (树形导航  ├────────────────────────────────────────┤
│  卷→章→   │ 可见视图折叠区（模块内闭环）               │
│  场景)    │  - 细纲/可见视图对照 · 重新生成 · 手改      │
│          ├────────────────────────────────────────┤
│          │ 正文工作区：                             │
│          │  阅读模式（markdown 渲染）               │
│          │    ↕ 「编辑」切换                        │
│          │  编辑模式（textarea）→ 选中 → 浮条改写    │
│          ├────────────────────────────────────────┤
│          │ [基于反馈重写]（展开输入框，全局重生成）    │
└──────────┴────────────────────────────────────────┘
```

- 场景列表：树形导航到场景（卷→章→场景，只导航、场景外节点不可选）；
- 可见视图在正文模块内闭环（细纲→可见视图→正文不用切模块）；场景无可见视图时主区提示先生成；
- 生成中：正文工作区**流式显示正文**（「正在写作…」+ 停止按钮），讨论模块零打扰；
- 反馈重生成（全局）收进操作条，与就地改写（局部）并列。

### 5.2 跨模块联动（2026-08-06 修订：已移除）

**修订**：讨论与正文是两个隔离沙箱，中间只靠大纲树场景链接（正文模块场景列表 = 大纲树投影）。~~正文生成完成 → 讨论模块对话流出现一条轻提示「第 3 场·小说版已生成 → 打开」~~——写作任务在讨论中**零痕迹**（含运行开始/结束与 AI 回答，§4.3 修订）；不再有「→ 打开」跳转提示（P1-6 修复维持：不插入「（生成正文：…）」用户消息）。

### 5.3 就地改写（revise，新任务类型）

- **仅限正文**；讨论流和大纲（草稿/正式版）的编辑模式完全不动；
- 触发：正文编辑模式（textarea）选中文本 → 浮动条；
  - 预设动作：更有张力 / 扩写 / 精简 / 润色；
  - **自定义输入**（与预设同管道，placeholder「告诉 AI 你想怎么改…」）——预设按钮不足以表达全部修改意图，自定义是必须项；
- 结果：**卡片预览**（流式）→ 接受 / 放弃 / 重试；
- **替换精度契约**：AI 只返回"选中区间的完整替换文本"（要删除返回空），替换 = 新文本替换原选区，确定性高，无 diff 匹配；
- 选区机制：编辑模式 textarea 的 selectionStart/End 直接对应文件区间；
- 任务白名单：read_visible_view / read_asset+list_assets / 该场景当前输出 / write_output（角色一致性可查设定）；
- 可逆：每次接受自动快照（复用 snapshots，文件小成本低）+ 正文模块内「撤销上次改写」（单级，不弹变更摘要面板；多级由版本历史兜底）。

## 6. 明确不做

- 工具调用卡片流、每消息 checkpoint、Plan/Act、diff 逐 hunk 审查、权限审批（§1）；
- 「材料」概念与一切相关 UI/文案（§3）；
- 空状态引导卡、三入口分类（§3：都是输入，不引导）；
- 整理计数/时间等红点式催促提示（§4.2）；
- 会话级预测式上下文视图（`inspectContext` 形态）——由每消息级调用详情替代（§4.7）；
- 讨论中的引用链接（AI 回答内节点/设定可点击跳转）——依赖 AI 输出结构化标记，破坏自然文风；审阅整理结果时的跳转已由总结消息的节点链接覆盖；
- Swipes 多版本候选（design.md §10 维持）。
